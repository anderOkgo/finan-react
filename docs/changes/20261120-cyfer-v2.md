# Cyfer version 2, the shared library

**Date:** 2026-11-20 · **Branch:** `feature/20261120-cyfer-v2` · **Released in:** production 2026-11-20 (from the branch, merged 2026-11-20)
**Implements:** `module-docs/apps/finan/SPEC.md` v0.10.2 (Local data row); the library itself:

**Change ID:** `20261120-cyfer-v2` (also in bitacora-react, animecream-react, module-api and cyfer-vanilla)

## Summary
`src/helpers/cyfer.js` is replaced by the owner's cyfer version 2, the same file in every project
(home: `github.com/anderOkgo/cyfer-vanilla`, `dist/js/cyfer.js`). Call sites do not change:
`cyfer().cy(text, set.salt)` and `cyfer().dcy(text, set.salt)` keep working, now synchronous
version 2. Version 2 works on UTF-8 bytes (no more accent stripping), with a random nonce, a SHA-256
key stream and a 4-byte check. A value that does not open gives `null` instead of throwing.

## Behavior by case
| Case | Before | Now |
|---|---|---|
| Session, countdown and table cache in `localStorage` | Old cyfer | Version 2, about half as long |
| A value stored before this change | Opened | Gives `null`: the user logs in once more; the cache and countdown reload from the API |
| A stored value that opens but is not JSON | Logged | Still logged (the existing `catch`) |
| Text with accents (`café`) | Came back as `cafe` | Comes back as written |

## Decisions
- **D1 — Same call shape.** The library exports a default `cyfer` that returns `{ cy, dcy, cyAsync,
  dcyAsync }`, so no call site changed. Finanz uses the synchronous pair (owner, Bitácora P77):
  compression would need async reads in the session, Tab and countdown code.
- **D2 — Tests:** the library's own test file (`src/helpers/__tests__/cyfer.test.js`) is copied with it.
  Three tests that wrote garbage into `localStorage` to reach the "cannot be read" log now write a value
  that opens but is not JSON. Three new tests check that garbage, or an old-format value, now gives
  nothing quietly.
